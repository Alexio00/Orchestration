# Orchestration

Разработка с чистого листа **General 5** — лёгкого PM-оркестратора для ведения проектов. Он помогает модели надёжно вести проект к результату без сложной системы оркестрации.

## Статус

**Выпущено: General 5.0.0.** Product Owner принял решение использовать эту версию как инструкции проекта. Фактическая активация считается завершённой после установки текста в настройках проекта.

## Назначение продукта

General 5 предназначен для проектной работы, в которой пользователь выступает Product Owner (PO), а модель — Project Manager (PM). Это не универсальный оркестратор для любых видов общения и задач.

## Границы продукта

- По умолчанию работает один агент.
- Инструменты, планирование и субагенты используются только при явной пользе.
- Продуктовые решения принимает PO; техническое выполнение остаётся в подтверждённых границах.
- Правила должны оставаться достаточно короткими, чтобы их можно было быстро прочитать, понять и адаптировать.
- Сложность добавляется только после подтверждённого дефекта, который нельзя устранить более простым правилом.

## Границы репозитория

В этом репозитории развивается только новая линия General 5.

Предыдущие версии, модули, исследования, релизы и история реализации остаются в архивном репозитории только для чтения: [Alexio00/Orchestration_old](https://github.com/Alexio00/Orchestration_old). Ничто из него не является нормативной частью General 5, пока решение не будет осознанно отобрано и заново сформулировано для новой версии.

## Режим эксплуатации и развития

- General 5.0.0 используется как неизменяемая активная версия после установки в инструкции проекта.
- Отклонение сначала фиксируется как наблюдение; действующий промпт не исправляется на месте.
- Изменение вносится только при воспроизводимом существенном дефекте, который нельзя устранить существующим правилом или более ясной формулировкой.
- Следующая версия разрабатывается отдельно от действующей: уточнение без изменения поведения выпускается как 5.0.1, изменение поведения или новое правило — как 5.1.0.
- Независимая проверка применяется при спорном или повторяющемся дефекте.
- Выпуск и последующая активация новой версии требуют отдельных решений PO.

## Жизненный цикл

Черновик → проверено → интегрировано → выпущено → активировано.

Каждый переход выполняется отдельно. Создание или изменение черновика не означает его выпуск или активацию.

Первая версия выпускается после редакционной проверки без предварительного пилота на реальных задачах. Практическая эксплуатация служит источником обратной связи; подтверждённые дефекты исправляются в последующих версиях, а выпущенная версия не переписывается задним числом.

## Язык документации

Основной язык всей документации проекта — русский. Английский сохраняется только там, где перевод повредит точности: в коде, командах, путях, идентификаторах, параметрах API, названиях продуктов и оригинальных сообщениях об ошибках.
