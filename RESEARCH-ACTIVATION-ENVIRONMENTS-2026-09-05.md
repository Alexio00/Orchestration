# Исследование сред активации General 5

Дата проверки: **5 сентября 2026**

Статус: **исследовательский результат; не является изменением General 5.0.0**

## Цель и метод

Проверить исходную сводку по ChatGPT, Codex, Claude, Claude Code, Qwen Studio и Qwen Code и подготовить основу единого протокола активации General 5.

Приоритет источников: официальная документация производителей и официальные репозитории. Используются статусы: **подтверждено**, **частично подтверждено**, **не подтверждено официально**. Быстро меняющиеся сведения требуют повторной проверки перед выпуском адаптера.

## Ключевые поправки к исходной сводке

1. **Qwen Code нельзя описывать как только веб-инструмент без проектного контекста.** Официальный репозиторий документирует терминальный агент, проектные QWEN.md и AGENTS.md, авто-память, командную память и специализированных субагентов.
2. **Лимиты файлов Claude были смешаны.** Официальная справка указывает до 500 МБ на файл и 20 файлов для загрузок в чат; для файлов проекта — 30 МБ на файл и неограниченное количество при ограничении общим контекстом.
3. **ChatGPT Projects и Codex имеют разные механизмы контекста.** ChatGPT Project хранит общие файлы, источники и инструкции; Codex CLI/IDE используют рабочую папку и репозиторные инструкции.
4. Утверждения о точных лимитах инструкций Qwen Studio, ChatGPT Library и несовместимости ChatGPT Work с project-only memory не подтверждены найденными официальными страницами. Их нельзя использовать как нормативную основу без отдельной проверки.
5. Ошибка Windows «Could not use this project for a local chat» может учитываться как наблюдаемый дефект, но не должна определять архитектуру переносимого протокола.

## Подтверждённые детали

### ChatGPT и Codex

Официальная документация OpenAI подтверждает:

- ChatGPT Project объединяет чаты, файлы, инструкции и подключённые источники; инструкции проекта действуют во всех его чатах.
- Один проект может содержать отдельные чаты Chat и ChatGPT Work.
- Codex CLI считает проектом каталог запуска; IDE — открытую папку или workspace.
- Для долговременных правил Codex рекомендует AGENTS.md или документацию в репозитории.
- Codex строит цепочку AGENTS.md от корня к рабочему каталогу; более близкие инструкции идут позже.
- Суммарный лимит автоматически загружаемых проектных инструкций Codex по умолчанию — 32 KiB.
- ChatGPT Work и Codex поддерживают субагентные процессы; они полезны для независимой параллельной работы, но расходуют больше токенов.
- Импорт в ChatGPT/Codex может переносить инструкции, настройки, skills, плагины, проекты и недавние сессии из поддерживаемых агентов, но это вспомогательная функция, а не универсальный межвендорный протокол.

### Claude и Claude Code

Официальная документация Anthropic подтверждает:

- Claude Project использует project instructions и project knowledge.
- Для платных планов RAG включается автоматически при приближении базы знаний к пределу контекста и может увеличить ёмкость до 10 раз.
- Файлы чата и проекта имеют разные лимиты: до 500 МБ и 20 файлов в чате; 30 МБ на файл проекта.
- Каждая Claude Code-сессия начинает с нового контекстного окна.
- Постоянный контекст обеспечивают CLAUDE.md; авто-память хранит выводы и предпочтения отдельно.
- Anthropic рекомендует держать CLAUDE.md конкретным и компактным, ориентир — менее 200 строк.
- Claude Code не читает AGENTS.md напрямую, но CLAUDE.md может импортировать его директивой @AGENTS.md.
- /context позволяет подтвердить загрузку инструкций.
- Пользовательского субагента рекомендуется создавать, когда один и тот же тип исполнителя запускается повторно с одинаковыми инструкциями.
- Для сложной передачи работы в cloud Anthropic рекомендует сохранить план в репозитории, закоммитить и отправить его, затем поручить cloud-сессии исполнение этого файла.

### Qwen Code

Официальный репозиторий QwenLM подтверждает:

- Каждая сессия начинает с нового контекстного окна.
- QWEN.md служит постоянным брифом; проектный файл следует хранить в Git.
- Qwen Code также читает AGENTS.md, что позволяет использовать общий межвендорный файл без дублирования.
- Авто-память локальна; team memory можно хранить в .qwen/team-memory/ и синхронизировать через Git.
- Пользовательские субагенты имеют отдельный контекст, специализированные инструкции и ограничиваемые инструменты.
- Экспериментальный Agent Team поддерживает несколько рабочих потоков, но не является необходимой частью базовой активации.

## Неопределённости

Пока нельзя считать подтверждёнными:

- точный лимит символов инструкций Qwen Studio;
- порядок приоритета инструкций и правила памяти Qwen Studio;
- точные лимиты и семантика ChatGPT Library;
- переключение default/project-only memory и его влияние на Work;
- единый опубликованный порядок приоритета глобальных и проектных инструкций ChatGPT Project;
- автоматическое чтение репозитория обычными чат-интерфейсами;
- полная матрица Cowork: локальные файлы, проектные инструкции, субагенты и наследование контекста;
- переносимость одной активационной проверки между всеми тарифами и аккаунтами.

## Практики передачи состояния

Из проверенных материалов складывается общий шаблон:

1. **Git — источник истины.** Нормативные инструкции и долговременные решения находятся в репозитории.
2. **Инструкции отделены от состояния.** AGENTS.md, CLAUDE.md и QWEN.md задают поведение; отдельный handoff-файл описывает текущую точку работы.
3. **Срез ссылается на исходники.** Он содержит commit SHA, решения, открытые вопросы и ссылки на нужные файлы, а не копию всего проекта.
4. **Локальная память необязательна.** Auto-memory помогает внутри продукта, но не считается переносимым источником истины.
5. **Новый исполнитель проверяет свежесть.** Сначала сравнивает SHA и ветку, затем читает только изменившиеся или указанные файлы.
6. **План можно исполнять отдельной сессией.** Практика Anthropic — сохранить утверждённый план в Git и запустить новую cloud-сессию на его исполнение.
7. **Активация требует квитанции.** Исполнитель сообщает, какие инструкции и состояние действительно загрузил.

## Черновая модель единого протокола активации

### Канонические артефакты

- GENERAL-5.md — неизменяемое версионированное ядро.
- AGENTS.md — переносимый репозиторный bootstrap для сред, которые его читают.
- CLAUDE.md — минимальный адаптер Claude Code с импортом @AGENTS.md.
- QWEN.md — необязательный минимальный адаптер Qwen Code; общий слой уже доступен через AGENTS.md.
- PROJECT-STATE.md — компактное текущее состояние проекта.
- adapters/ — инструкции для чат-интерфейсов и сред без автоматического чтения файлов.

### Bootstrap-процедура

1. Определить LLM, режим, доступ к файлам, Git, инструментам и субагентам.
2. Загрузить каноническое ядро и соответствующий адаптер.
3. Найти PROJECT-STATE.md.
4. Сравнить указанные repository, branch и commit SHA с фактическими.
5. При совпадении прочитать только файлы из раздела «Обязательный контекст».
6. При расхождении сообщить об устаревании и выборочно восстановить состояние из Git.
7. Выполнить capability probe без изменений проекта.
8. Вернуть activation receipt.

### Минимальная activation receipt

- среда и режим;
- версия General;
- источник ядра;
- загруженные файлы инструкций;
- repository / branch / commit;
- состояние handoff: актуально или устарело;
- доступные возможности;
- применённые fallback;
- блокировки и неопределённости.

### Минимальный PROJECT-STATE.md

- дата обновления;
- repository;
- branch;
- commit SHA;
- цель и критерий готовности;
- подтверждённый объём и ограничения;
- решения PO;
- завершённое;
- текущее состояние;
- открытые вопросы и риски;
- обязательный контекст: ссылки на 3–7 файлов;
- следующий шаг;
- инструкция восстановления при устаревшем SHA.

## Архитектурный вывод

Единый контур должен унифицировать **протокол**, а не интерфейс запуска:

- репозиторные агенты активируются через нативные instruction files;
- проекты чат-интерфейсов — через project instructions и подключённые файлы;
- обычные чаты — через короткий bootstrap-промпт;
- все варианты завершаются одинаковой activation receipt и используют одинаковый PROJECT-STATE.md.

Это позволяет сохранить одно ядро и изолировать различия сред в малых адаптерах.

## Влияние на вопрос о модулях

Исследование поддерживает промежуточное решение:

- не создавать полный набор модулей заранее;
- сначала использовать PM и встроенные универсальные субагенты;
- создавать лёгкий контракт роли или skill, когда один тип работы и инструкции повторяются;
- отдельный модуль оправдан, если нужны устойчивый системный промпт, ограниченный набор инструментов, независимый контекст или отдельные разрешения;
- описание роли должно быть коротким, а подробные инструкции загружаться только при вызове.

Это согласуется с правилом усложнения General 5 и рекомендациями OpenAI, Anthropic и Qwen о стоимости контекста и специализации.
