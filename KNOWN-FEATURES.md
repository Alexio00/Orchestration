# Принятые особенности General 5

Статус: действующий перечень. Эти особенности не считаются дефектами и не пересматриваются без нового воспроизводимого основания; условие пересмотра указано в каждом разделе. Дата решения PO указана в разделе.

## 1. Первоначальный запуск Codex и Qwen Code

Постоянная точка входа этих сред — корневой `AGENTS.md`. В новом репозитории без файла bootstrap не может запуститься только от открытия корня; предполагается использование доступного адаптера установки проекта. Отдельный глобальный установщик или обязательная стартовая команда сейчас не вводятся.

Пересмотреть, если живые тесты покажут повторяющиеся ошибки первоначального подключения.

## 2. Доверие к содержимому проектных источников

Bootstrap читает `PROJECT-STATE.md`, README, ТЗ, код и материалы PR без отдельного встроенного правила против prompt injection. Действующая иерархия инструкций среды и General 5 считается достаточной; специальная trust-boundary инструкция сейчас не добавляется.

Пересмотреть при воспроизводимом выполнении команды из источника данных или ложной фиксации решения PO.

## 3. Область предварительного разрешения cloud-адаптера

Установка адаптера владельцем разрешает подготовку файлов активации, отдельной ветки, commit/push и одного draft PR без repo allowlist. Разрешение ограничено изменениями активации; merge, direct push в base, monitoring, deployment и деструктивные действия по-прежнему требуют отдельных решений PO.

Пересмотреть, если одно окружение начнёт использоваться для репозиториев, где такое предварительное разрешение неприемлемо.

## 4. Механика делегирования вне payload

Статус: зафиксировано решением PO 2026-09-08.

Текст `OPS-DELEGATION.md` и `OPS-ROLES.md` не включается ни в `PROJECT-INSTRUCTIONS.md`, ни в `AGENTS.md`; `scripts/verify-artifacts.sh` запрещает их упоминание в адаптере проекта. В репозиторных средах они доступны по ссылке из `AGENTS.md` и читаются только после решения делегировать. В средах без репозитория механика делегирования недоступна; ссылка на публичный snapshot и перенос контракта в ядро не вводятся, чтобы не расходовать лимит инструкций и не дублировать правила.

Пересмотреть, если среда с субагентами и без репозитория даст воспроизводимый дефект делегирования.

## 5. Отсутствие поведенческого евала

Статус: зафиксировано решением PO 2026-09-08.

Спецификация сценариев, валидатор контракта и шаг CI удалены. Поведение General не измеряется: раннера и процедуры независимой оценки нет, baseline не собирается, эффект уточнений правил ядра остаётся неизмеренным. Продукт проверяется структурным контуром `verify-artifacts.sh` и живой активацией, подтверждаемой PO. Прежние сценарии остаются в истории Git и в архивном `Orchestration_old`.

Пересмотреть, если появится воспроизводимый поведенческий дефект, который нельзя локализовать без измерения.
