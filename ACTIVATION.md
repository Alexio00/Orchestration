# Активация General 5 в поддерживаемых средах

Статус: основной контур General 5.0.0 с Activation Bootstrap 1.0. Экспериментальные среды не входят.

## Общий контракт

Во всех средах действуют три независимых слоя:

1. `GENERAL-5.md` — стабильные правила PM.
2. `ACTIVATION-BOOTSTRAP.md` — автоматический preflight и безопасная установка инфраструктуры.
3. `PROJECT-STATE.md` — изменяемый снимок конкретного проекта.

Bootstrap выполняется перед первой содержательной работой в новой сессии как пролог к обычной задаче. Специальное стартовое сообщение пользователя не требуется.

После активации по запросу модель сообщает версию General и bootstrap, среду, репозиторий и ветку, `HEAD`, свежесть состояния, текущую цель, следующий шаг, изменённые файлы и расхождения.

## Артефакты

| Файл | Назначение |
|---|---|
| `GENERAL-5.md` | Каноническое выпущенное ядро General 5.0.0 |
| `ACTIVATION-BOOTSTRAP.md` | Канонический автоматический preflight |
| `PROJECT-INSTRUCTIONS.md` | Готовый текст для ChatGPT Project и Claude Project: General + bootstrap |
| `CLAUDE-CODE-SETUP.sh` | Готовый setup script облачного окружения Claude Code |

| `PROJECT-STATE.template.md` | Шаблон нового состояния |

## Первая поддерживаемая матрица

| Среда | Постоянная точка входа | Состояние | Первый запуск |
|---|---|---|---|
| ChatGPT Project Chat / Work | `PROJECT-INSTRUCTIONS.md` в инструкциях проекта | `PROJECT-STATE.md` в проекте или репозитории | Любая обычная задача запускает preflight |
| Claude Project | `PROJECT-INSTRUCTIONS.md` в Project Instructions | `PROJECT-STATE.md` в Project Knowledge | Любая обычная задача запускает preflight |
| Claude Code cloud | Глобальный адаптер, установленный `CLAUDE-CODE-SETUP.sh`; затем репозиторный `CLAUDE.md` | Корневой `PROJECT-STATE.md` | Любая обычная задача запускает preflight |
| Claude Code local | Корневой `CLAUDE.md` импортирует `AGENTS.md` | Корневой `PROJECT-STATE.md` | Открыть корень репозитория |
| Codex app / CLI / IDE / cloud | Корневой `AGENTS.md` | Корневой `PROJECT-STATE.md` | Открыть корень репозитория |

| Обычный чат без проекта | `GENERAL-5.md` и bootstrap как первое вложение или сообщение | `PROJECT-STATE.md` вторым вложением | Явно назначить файлы правилами и состоянием |

## ChatGPT Project и Claude Project

1. Скопируй весь `PROJECT-INSTRUCTIONS.md` в инструкции проекта.
2. Добавь `PROJECT-STATE.md` в знания проекта либо предоставь доступ к репозиторию.
3. Начинай новый чат сразу с обычной задачи: bootstrap сам проверит доступный контур.
4. Если среда не предоставляет изменяемый репозиторий, bootstrap не симулирует файловые изменения и использует доступные инструкции и состояние.
5. Обновляй инструкции проекта только при активации новой версии General или bootstrap.

## Claude Code cloud

### Настройка окружения

1. Открой selector окружения на `claude.ai/code`.
2. Создай отдельное окружение или отредактируй существующее.
3. Используй подходящий уровень сетевого доступа; General и bootstrap не требуют секретов или environment variables.
4. Скопируй весь `CLAUDE-CODE-SETUP.sh` в поле Setup script.
5. Сохрани окружение и используй его для новых cloud-сессий.

Setup script записывает полный глобальный адаптер непосредственно в управляемый блок системного `/etc/claude-code/CLAUDE.md` и сохраняет остальное содержимое файла. Внешний Markdown-импорт не используется: тест показал, что Claude Code cloud загрузил строку абсолютного импорта, но не подключил её содержимое. Setup script не изменяет выбранный репозиторий. Из-за кэширования он может выполняться не в каждой сессии; постоянный глобальный `CLAUDE.md` загружается Claude Code при запуске и выполняет per-repository preflight.

### Работа

1. Выбери репозиторий, ветку и настроенное окружение.
2. Отправь обычную задачу без команды активации.
3. Bootstrap проверит `CLAUDE.md`, `AGENTS.md` и `PROJECT-STATE.md`, безопасно подготовит недостающую инфраструктуру и затем продолжит задачу.
4. Созданные файлы входят в рабочий diff. Они станут доступны будущим чистым cloud-сессиям только после разрешённого сохранения в репозитории.
5. Для диагностики используй `/context`: `/etc/claude-code/CLAUDE.md` должен присутствовать среди memory files и занимать контекст, соответствующий полному адаптеру, а не одной строке импорта.

## Репозиторные среды

### Codex

Открой корень репозитория. Codex читает `AGENTS.md`, затем по его протоколу — `PROJECT-STATE.md`. Если файлов нет, используй адаптер установки проекта до обычной работы.

### Claude Code local

Корневой `CLAUDE.md` импортирует `AGENTS.md`. Для уже активированного репозитория отдельный глобальный адаптер не нужен.

### Qwen Code

Используй корневой `AGENTS.md`; отдельный `QWEN.md` не создаётся, пока тест не докажет необходимость.

## Безопасное обслуживание

- Отсутствующие файлы активации можно создавать автоматически в доступном изменяемом репозитории.
- В `CLAUDE.md` разрешено только недеструктивно добавить `@AGENTS.md`.
- В `AGENTS.md` автоматически изменяется только блок `GENERAL-5:BEGIN` — `GENERAL-5:END`.
- Стороннее содержимое, неоднозначные или повреждённые маркеры и более новая версия General не перезаписываются.
- Существующий `PROJECT-STATE.md` не заменяется целиком автоматически.
- Commit, push, PR, merge, публикация и deployment требуют соответствующего решения PO.

## Что обновлять

| Событие | General | Bootstrap | Адаптеры | `PROJECT-STATE.md` |
|---|---:|---:|---:|---:|
| Обычная работа | Нет | Нет | Нет | Только при checkpoint |
| Решение PO или завершение этапа | Нет | Нет | Нет | Да |
| Новая выпущенная версия General | Новый релиз | При необходимости | Пересобрать и активировать | Указать новую версию |
| Новая версия bootstrap | Нет | Новая версия | Пересобрать и активировать | Зафиксировать решение |
| Изменение среды | Нет | При необходимости | Только затронутый адаптер | При необходимости |

Таким образом, при повседневной работе меняется только состояние проекта. Инструкции и setup script обновляются отдельно и только при явной активации новой версии соответствующего слоя.
