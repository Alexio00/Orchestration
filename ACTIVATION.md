# Активация General 5 в поддерживаемых средах

Версии документа: General 5.0.3, Activation Bootstrap 1.3.0, Activation Git 1.3.0 и Claude Code Cloud Adapter 1.3.0. Статус: candidate; публикация и активация фиксируются отдельно в `PROJECT-STATE.md`; экспериментальные среды не входят.

## Общий контракт

Во всех средах действуют три независимых слоя:

1. `GENERAL-5.md` — стабильные правила PM.
2. `ACTIVATION-BOOTSTRAP.md` — автоматический preflight и безопасная установка инфраструктуры.
3. `PROJECT-STATE.md` — изменяемый снимок конкретного проекта.

Bootstrap выполняется перед первой содержательной работой новой сессии. После установки постоянной точки входа специальное стартовое сообщение не требуется; обычный чат сначала должен получить файлы или текст инструкций.

Перед первой содержательной работой модель один раз кратко сообщает версию General, репозиторий и ветку, `HEAD`, свежесть состояния, текущую цель, следующий шаг и расхождения. Расширенная квитанция с файлами, возможностями и изменениями выдаётся по запросу.

## Жизненный цикл

Единая последовательность: `draft → verified → integrated → released → published → activated`.

`verified` — успешная статическая и независимая проверка кандидата; `activated` — подтверждённая загрузка выпущенного артефакта новой сессией среды. Установка текста не равна активации. Статусы не пропускаются.

## ChatGPT Project и Claude Project

1. Скопируй весь `PROJECT-INSTRUCTIONS.md` в инструкции проекта.
2. Добавь `PROJECT-STATE.md` в знания проекта либо предоставь доступ к репозиторию.
3. Начинай новый чат сразу с обычной задачи: bootstrap сам проверит доступный контур.
4. Если среда не предоставляет изменяемый репозиторий, bootstrap не симулирует файловые изменения и использует доступные инструкции и состояние.
5. Обновляй инструкции проекта только при активации новой версии General или bootstrap.

## Claude Code cloud

### Настройка окружения

1. Открой selector окружения на `claude.ai/code`.
2. Создай отдельное окружение или отредактируй существующее.
3. Используй подходящий уровень сетевого доступа; General и bootstrap не требуют секретов или environment variables.
4. Скопируй весь `CLAUDE-CODE-SETUP.sh` в поле Setup script.
5. Сохрани окружение и используй его для новых cloud-сессий.

Setup script записывает полный глобальный адаптер непосредственно в управляемый блок системного `/etc/claude-code/CLAUDE.md` и сохраняет остальное содержимое файла. Внешний Markdown-импорт не используется: тест показал, что Claude Code cloud загрузил строку абсолютного импорта, но не подключил её содержимое. Setup script не изменяет выбранный репозиторий. Из-за кэширования он может выполняться не в каждой сессии; постоянный глобальный `CLAUDE.md` загружается Claude Code при запуске и выполняет per-repository preflight.

### Работа

1. Выбери репозиторий, ветку и настроенное окружение.
2. Отправь обычную задачу без команды активации.
3. До правок Bootstrap подтвердит полную выдачу открытых PR к целевой base и классифицирует кандидатов по фиксированному набору путей/маркеров. При нескольких кандидатах, неполной выдаче или конфликте остановится до решения PO. Затем проверит три файла и безопасно подготовит инфраструктуру. Снимок описывает проект по его документам, а задачу сессии — отдельно.
4. Проверь результат: bootstrap обязан проверить diff и сохранить только изменения активации через commit/push в отдельную ветку и один draft PR (или подходящий существующий PR). Без изменений новые commit/PR не нужны. Merge и мониторинг этим не разрешены.
5. Для диагностики используй `/context`: `/etc/claude-code/CLAUDE.md` должен присутствовать среди memory files и занимать контекст, соответствующий полному адаптеру, а не одной строке импорта.

## Репозиторные среды

### Codex

Открой корень репозитория. Codex читает `AGENTS.md`, затем по его протоколу — `PROJECT-STATE.md`. Если файлов нет, используй адаптер установки проекта до обычной работы.

### Claude Code local

Корневой `CLAUDE.md` импортирует `AGENTS.md`. Для уже активированного репозитория отдельный глобальный адаптер не нужен.

### Qwen Code

Используй корневой `AGENTS.md`; отдельный `QWEN.md` не создаётся, пока тест не докажет необходимость.

## Безопасное обслуживание

- Отсутствующие файлы активации можно создавать автоматически в доступном изменяемом репозитории.
- В `CLAUDE.md` разрешено только недеструктивно добавить `@AGENTS.md`.
- В `AGENTS.md` автоматически изменяется только блок `GENERAL-5:BEGIN` — `GENERAL-5:END`.
- Управляемый блок `AGENTS.md` обязан содержать точный маркер версии, репозиторный протокол чтения `PROJECT-STATE.md` и дословное ядро General.
- При отсутствии каждого из трёх файлов `CLAUDE.md`, `AGENTS.md` и `PROJECT-STATE.md` его создание обязательно, а не опционально.
- Стороннее содержимое, неоднозначные или повреждённые маркеры и более новая версия General не перезаписываются.
- Существующий `PROJECT-STATE.md` не заменяется целиком автоматически.
- Новый `PROJECT-STATE.md` создаётся по обязательной стандартной схеме, а не в свободном формате.
- Установка адаптера как активных инструкций разрешает единый сценарий подключения, включая commit/push и один PR только для изменений активации. Чтение документа само по себе разрешением не является.
- Повторно используй подходящий PR подключения; несколько кандидатов, конфликт или посторонние изменения — остановка до сохранения.
- Не включай чужие рабочие/staged-изменения; проверяй весь diff ветки, а не только последний commit.
- Явный read-only запрос и режим, более узкое разрешение и ограничения инструментов имеют приоритет. При read-only никаких записей и GitHub-изменений.
- Merge/auto-merge, прямой push в основную ветку, подписки, мониторинг, отложенные задачи и deployment требуют отдельных решений PO.
- Файлы в PR — «Подготовлено к подключению»; «Подключено в основной ветке» — только после проверки их наличия в ней. При неполном сохранении сообщай фактический этап.

## Что обновлять

| Событие | General | Bootstrap | Адаптеры | `PROJECT-STATE.md` |
|---|---:|---:|---:|---:|
| Обычная работа | Нет | Нет | Нет | Только при checkpoint |
| Решение PO или завершение этапа | Нет | Нет | Нет | Да |
| Новая выпущенная версия General | Новый релиз | При необходимости | Пересобрать и активировать | Указать новую версию |
| Новая версия bootstrap | Нет | Новая версия | Пересобрать и активировать | Зафиксировать решение |
| Изменение среды | Нет | При необходимости | Только затронутый адаптер | При необходимости |

Таким образом, при повседневной работе меняется только состояние проекта. Инструкции и setup script обновляются отдельно и только при явной активации новой версии соответствующего слоя.

## Troubleshooting

| Сигнал | Безопасное действие |
|---|---|
| Повреждённые, вложенные или обратные маркеры | Не исправлять автоматически; сохранить файл и передать PO точные строки |
| Более новая версия адаптера | Не выполнять downgrade; проверить источник версии и запросить решение PO |
| Несколько activation PR или неверный marker | Не создавать PR; перечислить кандидатов, base и changed files |
| Пагинация не доказана | Остановить запись; повторить запрос с явной полной пагинацией |
| Permission denied или подтверждение | Не обходить; указать достигнутый этап и требуемое право |
| Нет `PAGES_REPO_TOKEN` | Публикации нет даже при зелёном workflow; настроить token и повторить контролируемо |
| Глобальный файл отсутствует в `/context` | Проверить полный setup, `/etc/claude-code/CLAUDE.md` и новую сессию |

После восстановления повтори read-only preflight. Не удаляй маркеры, ветки или PR без решения PO.

## Проверка Bootstrap 1.3.0

Текущая версия разделяет протокол по применимости среды: `ACTIVATION-BOOTSTRAP.md` действует везде, дополнение «Работа с репозиторием» поставляется только туда, где репозиторий доступен. Адаптер ChatGPT Project собирается без дополнения и укладывается в лимит инструкций; cloud-адаптер Claude Code получает обе части. Правила 3, 4 и 7 ядра уточнены; новых правил нет. Механика делегирования и роли исполнителей вынесены в `OPS-DELEGATION.md` и `OPS-ROLES.md` вне контекста старта. Принятые PO особенности — в `KNOWN-FEATURES.md`. История версий — в git log и release notes.

Candidate требует проверки до выпуска и живой активации.

| Сценарий | Ожидаемый результат |
|---|---|
| Новый проект без файлов; обычное «подключись к проекту» | Три файла → проверка diff → commit/push → один draft PR → отчёт и остановка |
| До любых правок, создания ветки и commit | Полный поиск открытых PR репозитория по целевой base, без ограничения текущей head; ветка среды не отменяет поиск |
| Несколько PR активации в одну base | Остановка до решения PO; новый PR не создаётся |
| Поиск PR недоступен или выдача неполна | Остановка записи, не вывод «PR нет» |
| Цель есть в DRAFT ТЗ, новой задачи нет | В состоянии цель/границы проекта со ссылкой и статусом DRAFT; следующая задача отдельно, утверждение PO не выдумано |
| Повторное подключение | Подходящий PR используется повторно; без изменений нет новых commit/PR |
| Явное «проверь подключение, ничего не меняй» | Только проверка; файлы, Git-ветки и GitHub не изменяются |
| Чужие изменения в файлах/staging или в PR | Чужое не публикуется; при невозможности изоляции — остановка |
| Отказ доступа / обязательное подтверждение | Нет обхода; честно указан достигнутый этап |
| После создания PR | Нет merge/auto-merge, подписок, мониторинга, cron/check-in без отдельного решения |

Не использовать новый PR вместо существующего только ради теста. Для чистого теста создания выбрать разрешённый PO тестовый репозиторий без открытого PR активации; сценарий с существующим PR проверять отдельно.

Настройки среды пользователю нужно обновить один раз: полный новый setup script, затем новая сессия; для ChatGPT/Claude Project — полный PROJECT-INSTRUCTIONS.md. Репозиторный PR не активирует автоматически новый текст в настройках среды.
