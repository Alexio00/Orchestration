## Риски и расхождения

- Дословное ядро и bootstrap дублируются в адаптерах; их совпадение проверяется при каждой пересборке.
- По предыдущим тестам в DICOM созданы PR #1 и #2; их текущее состояние этим изменением не проверялось и не менялось. Перед новым тестом проверить существующие PR, не создавать дубликаты; merge остаётся отдельным решением.
- Разрешение на сохранение ограничено изменениями активации и одним PR; оно не распространяется на код проекта, merge и мониторинг. Сбой сохранения отражается как неполный статус, а не успешное подключение.
- Новая сессия от основной ветки не получает файлы из немерженного PR; обновление файлов в Orchestration также не обновляет настройки внешнего окружения.
- Правила среды могут запускать собственные PR-автоматизации. При несовместимости сообщить ограничение, не заявлять соблюдение запрета без доказательств.
- Некоторые среды могут изменить механизм загрузки инструкций; поведение проверяется отдельно для каждого режима.
